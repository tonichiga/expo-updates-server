# Панель керування {#панель-управления}

Адмінка використовує спільний UI kit shadcn/ui (Radix), Tailwind CSS 4, Lucide і Recharts. Вихідний код компонентів розташований у `components/ui`, тема — в `app/globals.css`, оболонка — в `components/admin`. Світла й темна теми використовують однакові семантичні токени. Нові сторінки мають використовувати ці компоненти й токени, зберігаючи серверну перевірку сесії в `app/updates/layout.tsx`.

## Навігація та дані {#навигация-и-данные}

- **Встановлення** (`/updates/devices`): спільні серверні фільтри, KPI, денна активність, розподіл версій, когорти та реєстр. Пошук підтримує частину ID встановлення. Повні ідентифікатори й діагностика відкриваються натисканням на ID.
- **OTA-оновлення** (`/updates`): публікації, сортування, пагінація та редагування. Аварійна зупинка розповсюдження розташована в розкривній панелі «Керування».
- **Вбудовані збірки** й **Аварійні маршрути** зберігають наявні обмеження за ролями та дії керування.

Фільтри застосовуються кнопкою «Застосувати» до всієї вибірки. Помилка запиту залишає попередній результат із явним повідомленням. Якщо остання сторінка зникла під час оновлення, реєстр переходить на останню наявну сторінку. Статистика рахує встановлення, а не унікальних людей.

Семантика денних даних, когорт, утримання та міграція БД: [телеметрія встановлень](./installation-telemetry.md). Для наявної бази потрібна міграція `2026-10-22-device-analytics.sql`; нова база отримує її з канонічного `schema.sql`.

## Перевірка інтерфейсу {#проверка-интерфеиса}

Під час змін перевіряйте ширини 1440 і 390 px, обидві теми, порожні фільтри та їх скидання, розкриття й копіювання ID, клавіатурне закриття бічних панелей із поверненням фокуса, повтор пагінації після помилки та зменшення кількості записів на останній сторінці. Таблиці можуть прокручуватися всередині картки; горизонтальне прокручування всієї сторінки не потрібне. Історію до початку збору не можна замінювати нулями або демонстраційними даними.

Команди перевірки: `npm run lint`, `npx tsc --noEmit`, `npm test`, `npm run build`, `npm run installer:check`. Нові папки інтерфейсу включені до шаблону npm-інсталятора, тому панель отримує той самий інтерфейс під час встановлення з коробки.

## Мова інтерфейсу {#interface-language}

За замовчуванням адмінка використовує англійську, незалежно від мови браузера. Виберіть **English**, **Русский** або **Українська** на сторінці входу чи в шапці. Вибір зберігається в cookie `ota-locale` на рік і застосовується сервером під час наступного завантаження. Невідомі значення мови замінюються англійською.

Зміна мови зберігає фільтри й незбережені дані форм та одразу перекладає вже показані повідомлення. Числа й дати форматуються вибраною мовою. Межі дат аналітики залишаються в UTC. Усі екрани адмінки, включно з аварійним відновленням, політиками доставки та каталогом Guard, використовують одну мову.

Переклади розташовані в `src/client/i18n/`: `en.json`, `ru.json` і `uk.json` мають мати однакові ключі й підстановки. Наявні ключі — початкові російські або англійські повідомлення; англійські відповідники також приймаються для помилок API та підписів. Використовуйте `useI18n().t` для тексту інтерфейсу й `useFormatters()` для аналітики. Зберігайте повідомлення як початковий ключ або `TranslationMessage` зі значеннями підстановок і перекладайте під час відображення, щоб вони змінювалися разом із мовою.

Перекладайте відображувані підписи переліків, зберігаючи значення API. Не перекладайте ID, JSON, імена пристроїв і каналів або повідомлення користувача. Невідомі технічні помилки показуються як є. Тести словників і перемикання перевіряють повноту, підстановки, збережені налаштування, форми та повідомлення. Додавання мови потребує явного підтримуваного значення, словника й пункту вибору; мова браузера навмисно не визначає початкового вибору.
