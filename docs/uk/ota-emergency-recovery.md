# Аварійне відновлення OTA {#аварииное-восстановление-ota}

## Глобальна аварійна зупинка {#глобальная-аварииная-остановка}

Якщо потрібно негайно припинити **будь-яке** розповсюдження OTA, скористайтеся глобальним перемикачем `ACTIVE/BLOCKED` на `/updates`. Він має пріоритет над усіма аварійними маршрутами: маніфест поверне `noUpdateAvailable`, а вже видані посилання `/api/assets` перестануть віддавати дані й відповідатимуть `503 no-store`.

Укажіть причину або номер інциденту, підтвердьте ввімкнення та перевірте URL маніфесту й ресурсу. Після виправлення перевірте вказівники каналів, підтвердьте зняття блокування та повторіть перевірки для iOS і Android.

RPC перемикача й тригери змін у БД використовують одне транзакційне advisory-блокування. Тому паралельна активація або зміна каналу або завершиться до ввімкнення `BLOCKED`, або дочекається його й буде відхилена PostgreSQL із SQLSTATE `P0OTA` та повідомленням `OTA_DISTRIBUTION_BLOCKED`. Деактивація, додавання неактивних чернеток і безпечне редагування метаданих залишаються доступними. Не вимикайте захисні тригери під час інциденту.

Нові маніфести використовують URL серверного проксі `/api/assets` із перевіркою блокування. Уже видані старими версіями сервера незмінні URL сховища або CDN неможливо відкликати цим перемикачем; ураховуйте це обмеження старих URL під час реагування на інцидент.

Аварійний маршрут потрібен, коли опублікована нативна збірка запитує неправильний канал Expo. JavaScript OTA не може змінити канал, записаний в Android Manifest або iOS Expo.plist, тому сервер перенаправляє лише проблемну збірку.

Правило застосовується лише за точного збігу:

- `expo-embedded-update-id`;
- версії середовища виконання;
- платформи;
- початкового каналу.

Не можна перенаправляти все середовище виконання: збірки для розробки та production можуть використовувати однакову версію середовища виконання.

## Підготовка БД {#подготовка-бд}

```bash
psql "$DATABASE_URL" -f docs/migrations/schema.sql
```

Якщо раніше правила зберігалися в `config/ota-emergency-channel-redirects.json`, імпортуйте їх до розгортання:

```bash
npm run emergency:import
```

Після успішного імпорту сервер більше не використовує JSON-файл.

## Керування {#управление}

Відкрийте:

```text
/updates/emergency-redirects
```

Ролі `admin` і `operator` можуть:

- створювати та редагувати правила;
- вмикати й вимикати перенаправлення;
- перемикати режими `pinned` і `follow`;
- видаляти правила.

Роль `viewer` має доступ лише для читання.

## Режими {#режимы}

### Закріплене оновлення (Pinned) {#pinned}

Сервер дозволяє лише `expectedUpdateId`. Якщо цільовий канал указує на інше оновлення, пристрій отримує `noUpdateAvailable`.

Використовуйте `pinned` під час початкового відновлення, щоб проблемна збірка отримала лише перевірене OTA для відновлення.

### Слідування за каналом (Follow) {#follow}

Сервер використовує поточне активне або останнє оновлення цільового каналу. Після успішного встановлення OTA для відновлення правило можна перемкнути в `follow`, щоб стара нативна збірка продовжила отримувати звичайні оновлення.

## Приклад інциденту {#пример-инцидента}

Збірку Android може бути опубліковано з такими параметрами:

```text
runtime: 1.1.20
native channel: development
expected environment: production
```

Екран застосунку водночас може показувати `production`, якщо читає JavaScript-конфігурацію. Expo Updates однаково надішле:

```text
expo-channel-name: development
```

Для проблемного вбудованого оновлення створіть правило:

```text
platform: android
runtimeVersion: 1.1.20
fromChannel: development
toChannel: production
targetMode: pinned
expectedUpdateId: <verified-recovery-update-id>
```

Після підтвердження відновлення перемкніть правило в `follow`.

## Перевірка {#проверка}

```bash
curl -fsS \
  'https://updates.example.com/api/manifest' \
  -H 'expo-protocol-version: 1' \
  -H 'expo-platform: android' \
  -H 'expo-runtime-version: 1.1.20' \
  -H 'expo-channel-name: development' \
  -H 'expo-embedded-update-id: <affected-embedded-update-id>'
```

Переконайтеся, що складений маніфест містить очікуване оновлення та URL ресурсів цільового каналу.
