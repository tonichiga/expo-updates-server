# Создание сервера через NPX {#create-a-server-with-npx}

npm-инициализатор — самый быстрый способ создать самостоятельную копию Expo Updates Server. Требуется Node.js 20.9 или новее.

```bash
npx create-expo-updates-server@latest my-server
cd my-server
```

Можно также инициализировать пустой текущий каталог:

```bash
mkdir my-server
cd my-server
npx create-expo-updates-server@latest .
```

`npx` скачивает опубликованный пакет инициализатора из npm. После запуска сам инициализатор не делает сетевых запросов: шаблон сервера и его манифест SHA-256 включены в пакет.

Для именованного каталога успешный текстовый вывод выглядит так (интерактивные терминалы добавляют цвет):

```text
✓ Expo Updates Server project files created
Project: /path/to/my-server

Next steps (Docker):
  1. cd -- 'my-server'
  2. npm ci
  3. Follow docs/getting-started.md: prepare settings and signing keys before starting Docker.

Next steps (npm):
  1. cd -- 'my-server'
  2. npm ci
  3. Follow docs/operations-guide.md: configure database, storage and signing keys before startup.
```

При использовании `.` лишний шаг `cd` пропускается. Цвет отключён, если вывод не является TTY или задана переменная окружения `NO_COLOR`.

## Безопасность установки {#safety-behavior}

Инициализатор:

- принимает ровно один каталог назначения;
- требует, чтобы именованный путь назначения не существовал, и отклоняет существующие пустые и непустые каталоги, файлы и символические ссылки;
- принимает существующий каталог только тогда, когда он в точности является текущим и не содержит видимых или скрытых элементов;
- создаёт уникальный соседний временный каталог с правами `0700`;
- собирает весь проект во временном каталоге и проверяет полный набор путей, типы файлов, размеры и хеши SHA-256 до установки;
- устанавливает отсутствующий именованный каталог переименованием временного каталога;
- непосредственно перед установкой в `.` повторно проверяет устройство, inode и пустоту текущего каталога, создаёт каталоги исключительно, копирует файлы без перезаписи и проверяет итоговый набор путей, размеры и хеши SHA-256;
- никогда не перезаписывает элементы, обнаруженные при установке в `.`, и никогда не удаляет текущий каталог рекурсивно;
- после начала подготовки оставляет уникальный временный каталог при ошибке и сообщает его точный путь для ручной проверки или удаления; если в `.` остался частичный результат установки, он также указывается для проверки.

Именованный каталог назначения должен отсутствовать на протяжении всей команды. Если другой процесс создаст файл, символическую ссылку или непустой каталог до финального переименования, инициализатор завершится с ошибкой и оставит его без изменений. Переносимые файловые API не предоставляют кроссплатформенное атомарное переименование каталога без перезаписи. В узком окне гонки, когда другой процесс создаёт пустой каталог назначения после последней проверки отсутствия, переименование может заменить этот пустой каталог.

Установка в `.` переносит элементы, а не заменяет сам текущий каталог. Исключительные операции не дают перезаписать элемент, появившийся по пути назначения при обычной параллельной работе. Если установка завершится ошибкой после создания части элементов, они намеренно не удаляются: их уже нельзя безопасно отличить от пользовательских изменений. Вручную проверьте указанный текущий каталог и временный снимок. Эти проверки защищают от обычных гонок файловой системы, а не от другого процесса того же пользователя.

Временный каталог содержит только публичные файлы шаблона. При успехе он становится именованным каталогом назначения либо удаляется после проверенного переноса в `.`, поэтому временных каталогов не остаётся.

Инициализатор намеренно не устанавливает зависимости, не создаёт Git-репозиторий, не записывает `.env` и не генерирует ключи подписи или другие секреты. Параметра `--force` нет.

## Запуск созданного проекта {#start-the-generated-project}

Последовательно выполните встроенное руководство [«Быстрый старт»](./getting-started.md): окружение, ключи подписи, запуск Docker, администратор, URL для телефона, настройка приложения, нативная сборка и первое OTA. Для `configure-app` на хосте нужны Node/npm и `npm ci`, даже если сервер работает в Docker.

Для размещённой инфраструктуры используйте [настройку Supabase](./supabase-setup.md) и [руководство по эксплуатации](./operations-guide.md). Настройте БД, хранилище и ключ подписи до запуска сервера через npm.

Пакет содержит шаблон из зафиксированного коммита исходников. Неопубликованная функция в рабочей копии недоступна через `npx ...@latest`; сопровождающим нужно следовать [процессу релиза](./publishing-npm-installer.md).

## Воспроизводимость и исходники {#reproducibility-and-source}

Каждый опубликованный пакет содержит отфильтрованный снимок, байты которого читаются напрямую из объектов Git зафиксированного коммита в [tonichiga/expo-updates-server](https://github.com/tonichiga/expo-updates-server). Изменённые или неотслеживаемые файлы рабочей копии не влияют на этот снимок. Пакет записывает точный коммит, размер и SHA-256 каждого создаваемого файла. Результаты сборки, учётные данные, заполненные секретные значения, реальные файлы окружения, внутренние планы и сам инициализатор исключены.
