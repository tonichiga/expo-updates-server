# Аварийное восстановление OTA {#аварииное-восстановление-ota}

## Глобальная аварийная остановка {#глобальная-аварииная-остановка}

Если необходимо немедленно прекратить **любую** раздачу OTA, используйте глобальный переключатель `ACTIVE/BLOCKED` на `/updates`. Он имеет приоритет над всеми аварийными маршрутами: манифест вернёт `noUpdateAvailable`, а уже выданные ссылки `/api/assets` перестанут отдавать данные и ответят `503 no-store`.

Укажите причину или номер инцидента, подтвердите включение и проверьте URL манифеста и ресурса. После исправления проверьте указатели каналов, подтвердите снятие блокировки и повторите проверки для iOS и Android.

RPC переключателя и триггеры изменений в БД используют одну транзакционную advisory-блокировку. Поэтому параллельная активация или изменение канала либо завершится до включения `BLOCKED`, либо дождётся его и будет отклонено PostgreSQL с SQLSTATE `P0OTA` и сообщением `OTA_DISTRIBUTION_BLOCKED`. Деактивация, добавление неактивных черновиков и безопасное редактирование метаданных остаются доступны. Не отключайте защитные триггеры во время инцидента.

Новые манифесты используют URL серверного прокси `/api/assets` с проверкой блокировки. Уже выданные старыми версиями сервера неизменяемые URL хранилища или CDN отозвать этим переключателем невозможно; учитывайте это ограничение старых URL при реагировании на инцидент.

Аварийный маршрут нужен, когда опубликованная нативная сборка запрашивает неправильный канал Expo. JavaScript OTA не может изменить канал, записанный в Android Manifest или iOS Expo.plist, поэтому сервер перенаправляет только затронутую сборку.

Правило применяется только при точном совпадении:

- `expo-embedded-update-id`;
- версии среды выполнения;
- платформы;
- исходного канала.

Нельзя перенаправлять всю среду выполнения: сборки для разработки и production могут использовать одинаковую версию среды выполнения.

## Подготовка БД {#подготовка-бд}

```bash
psql "$DATABASE_URL" -f docs/migrations/schema.sql
```

Если раньше правила хранились в `config/ota-emergency-channel-redirects.json`, импортируйте их до развёртывания:

```bash
npm run emergency:import
```

После успешного импорта сервер больше не использует JSON-файл.

## Управление {#управление}

Откройте:

```text
/updates/emergency-redirects
```

Роли `admin` и `operator` могут:

- создавать и редактировать правила;
- включать и выключать перенаправления;
- переключать режимы `pinned` и `follow`;
- удалять правила.

Роль `viewer` имеет доступ только для чтения.

## Режимы {#режимы}

### Закреплённое обновление (Pinned) {#pinned}

Сервер разрешает только `expectedUpdateId`. Если целевой канал указывает на другое обновление, устройство получает `noUpdateAvailable`.

Используйте `pinned` при первичном восстановлении, чтобы затронутая сборка получила только проверенное OTA для восстановления.

### Следование за каналом (Follow) {#follow}

Сервер использует текущее активное или последнее обновление целевого канала. После успешной установки OTA для восстановления правило можно переключить в `follow`, чтобы старая нативная сборка продолжила получать обычные обновления.

## Пример инцидента {#пример-инцидента}

Сборка Android может быть опубликована с такими параметрами:

```text
runtime: 1.1.20
native channel: development
expected environment: production
```

Экран приложения при этом может показывать `production`, если читает JavaScript-конфигурацию. Expo Updates всё равно отправит:

```text
expo-channel-name: development
```

Для затронутого встроенного обновления создайте правило:

```text
platform: android
runtimeVersion: 1.1.20
fromChannel: development
toChannel: production
targetMode: pinned
expectedUpdateId: <verified-recovery-update-id>
```

После подтверждения восстановления переключите правило в `follow`.

## Проверка {#проверка}

```bash
curl -fsS \
  'https://updates.example.com/api/manifest' \
  -H 'expo-protocol-version: 1' \
  -H 'expo-platform: android' \
  -H 'expo-runtime-version: 1.1.20' \
  -H 'expo-channel-name: development' \
  -H 'expo-embedded-update-id: <affected-embedded-update-id>'
```

Убедитесь, что составной манифест содержит ожидаемое обновление и URL ресурсов целевого канала.
