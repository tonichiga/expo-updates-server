# Панель управления {#панель-управления}

Админка использует общий UI kit shadcn/ui (Radix), Tailwind CSS 4, Lucide и Recharts. Исходники компонентов находятся в `components/ui`, тема — в `app/globals.css`, оболочка — в `components/admin`. Светлая и тёмная темы используют одни семантические токены. Новые страницы должны использовать эти компоненты и токены, сохраняя серверную проверку сессии в `app/updates/layout.tsx`.

## Навигация и данные {#навигация-и-данные}

- **Установки** (`/updates/devices`): общие серверные фильтры, KPI, дневная активность, распределение версий, когорты и реестр. Поиск поддерживает часть ID установки. Полные идентификаторы и диагностика открываются по нажатию на ID.
- **OTA-обновления** (`/updates`): публикации, сортировка, пагинация и редактирование. Аварийная остановка распространения находится в раскрываемой панели «Управление».
- **Встроенные сборки** и **Аварийные маршруты** сохраняют существующие ограничения по ролям и действия управления.

Фильтры применяются кнопкой «Применить» ко всей выборке. Ошибка запроса оставляет предыдущий результат с явным сообщением. Если последняя страница исчезла при обновлении, реестр переходит на последнюю существующую страницу. Статистика считает установки, а не уникальных людей.

Семантика дневных данных, когорт, возвращаемости и миграция БД: [телеметрия установок](./installation-telemetry.md). Для существующей базы нужна миграция `2026-10-22-device-analytics.sql`; новая база получает её из канонического `schema.sql`.

## Проверка интерфейса {#проверка-интерфеиса}

При изменениях проверяйте ширины 1440 и 390 px, обе темы, пустые фильтры и их сброс, раскрытие и копирование ID, клавиатурное закрытие боковых панелей с возвратом фокуса, повтор пагинации после ошибки и уменьшение числа записей на последней странице. Таблицы могут прокручиваться внутри карточки; горизонтальная прокрутка всей страницы не нужна. Историю до начала сбора нельзя заменять нулями или демонстрационными данными.

Команды проверки: `npm run lint`, `npx tsc --noEmit`, `npm test`, `npm run build`, `npm run installer:check`. Новые папки интерфейса включены в шаблон npm-установщика, поэтому панель получает тот же интерфейс при установке из коробки.

## Язык интерфейса {#interface-language}

По умолчанию админка использует английский, независимо от языка браузера. Выберите **English**, **Русский** или **Українська** на странице входа или в шапке. Выбор сохраняется в cookie `ota-locale` на год и применяется сервером при следующей загрузке. Неизвестные значения языка заменяются английским.

Смена языка сохраняет фильтры и несохранённые данные форм и сразу переводит уже показанные уведомления. Числа и даты форматируются в выбранном языке. Границы дат аналитики остаются в UTC. Все экраны админки, включая аварийное восстановление, политики доставки и каталог Guard, используют один язык.

Переводы находятся в `src/client/i18n/`: `en.json`, `ru.json` и `uk.json` должны иметь одинаковые ключи и подстановки. Существующие ключи — исходные русские или английские сообщения; английские эквиваленты также принимаются для ошибок API и подписей. Используйте `useI18n().t` для текста интерфейса и `useFormatters()` для аналитики. Храните уведомления как исходный ключ или `TranslationMessage` со значениями подстановок и переводите при отображении, чтобы они менялись вместе с языком.

Переводите отображаемые подписи перечислений, сохраняя значения API. Не переводите ID, JSON, имена устройств и каналов или пользовательские сообщения. Неизвестные технические ошибки показываются как есть. Тесты словарей и переключения проверяют полноту, подстановки, сохранённые настройки, формы и уведомления. Добавление языка требует явного поддерживаемого значения, словаря и пункта выбора; язык браузера намеренно не определяет начальный выбор.
